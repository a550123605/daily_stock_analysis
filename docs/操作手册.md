## 1. 它能做什么

一套跑在自己电脑上的股票分析工作台：抓行情 → 搜新闻 → 算指标 → 让大模型给结论 → 存库 → 邮件推送 → 网页随时翻看。

| 能力 | 说明 |
|---|---|
| 多市场行情 | A 股、ETF、港股、美股（含 ETF），日线与实时报价 |
| 技术面 | 均线排列、MACD、KDJ、RSI、布林带、量能、趋势强度 |
| 消息面 | 接入博查搜索，抓业绩预告、公告、资金流向、行业动态 |
| 决策报告 | 每只票输出评级（买入/观望/卖出）+ 评分 + 操作建议 + 风险点 |
| Web 工作台 | 10 个页面：首页、问股、持仓、决策信号、选股、数据中心、回测、预警、用量、设置 |
| 定时任务 | 每个交易日固定时间自动跑，非交易日自动跳过 |
| 邮件推送 | 结果自动发到邮箱，支持合并成一封 |
| 回测 | 用历史数据验证策略表现 |
| 持仓管理 | 记录成本、盈亏、仓位，结合分析给出提示 |

**它不是什么东西**：不是交易软件，不下单、不接券商；评分是大模型基于当日信息的判断，**不是买卖信号**（详见第 11 节）。

## 2. 首次安装

### 2.1 前置条件

| 项目 | 要求 | 检查命令 |
|---|---|---|
| Python | 3.10+（本项目实测 3.13） | `python --version` |
| 磁盘 | ≥ 2 GB（依赖约 400 MB） | — |
| 网络 | 能访问 DeepSeek API；美股需要能访问 Yahoo | — |
| 大模型 Key | 必需，没有就出不来报告 | — |

### 2.2 安装步骤

```bash
git clone https://github.com/a550123605/daily_stock_analysis.git
cd daily_stock_analysis

# 建独立虚拟环境（推荐，避免污染系统 Python）
python -m venv ../dsa-env
../dsa-env/Scripts/python.exe -m pip install -r requirements.txt

# 生成配置
copy .env.example .env
```

### 2.3 最少要填的 4 项

打开 `.env`，**这四项不填就跑不起来或没有报告**：

```ini
# 1) 大模型（DeepSeek 最省事）
DEEPSEEK_API_KEY=sk-xxxxxxxx
# 2) 要盯的标的，逗号分隔；A股写6位代码，美股写代码（BRK.B 这种带点号可以）
STOCK_LIST=510300,600036,601318,KO,VOO
# 3) 邮件推送（QQ/163 用授权码，不是登录密码）
EMAIL_SENDER=you@qq.com
EMAIL_PASSWORD=xxxxxxxxxxxxxxxx
EMAIL_RECEIVERS=you@qq.com
# 4) 新闻搜索（不填则报告的"利好/利空/公告"基本是空的）
BOCHA_API_KEYS=sk-xxxxxxxx
```

> 邮件授权码获取：QQ 邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成授权码。

### 2.4 验证安装

```bash
../dsa-env/Scripts/python.exe main.py --dry-run
```

`--dry-run` 会跑完整流程但**不发邮件**。看到报告输出即安装成功。

## 3. 启动与停止

### 3.1 三种启动方式

| 方式 | 命令 | 适用场景 |
|---|---|---|
| **双击脚本**（推荐） | `启动股票仪表盘.bat` | 日常使用，自动开浏览器 |
| 只开工作台 | `python main.py --serve` | 手动排查问题 |
| 工作台 + 定时 | `python main.py --serve --schedule` | 想让它一直挂着自动跑 |

启动后浏览器打开 **http://127.0.0.1:8000**，建议加入书签。

### 3.2 停止

- 双击脚本启动的：**直接关掉那个黑色命令行窗口**（或按 `Ctrl+C`）。
- 后台残留进程占用端口时：

```bash
netstat -ano | findstr :8000     # 查到 PID
taskkill /PID <PID> /F
```

### 3.3 关于"关掉窗口就停了"

API 服务是前台进程，窗口关闭 = 服务停止。想让它在后台常驻，二选一：

- 用「启动股票仪表盘.bat」，窗口最小化别关；
- 或在 Windows 任务计划程序里注册开机自启（触发程序填 `pythonw.exe main.py --serve`）。

## 5. 日常使用流程

### 场景 A：收盘后看一眼（最省事）

1. 什么都不用做——定时任务会在 **每个交易日 18:00** 自动跑完并发邮件。
2. 想看细节再打开仪表盘翻历史报告。

### 场景 B：盘中临时想分析某只票

1. 打开仪表盘 → 首页「手动分析」→ 输入代码 → 提交。
2. 首次分析会顺带生成当日大盘复盘（约 2.5 分钟）；之后 4 小时内的分析都会复用，不再重复跑。

### 场景 C：想先看大盘再决定跑哪些票

1. 双击 `预热大盘.bat`（或 `python 预热大盘.py`）。
2. 生成完毕后，后续所有个股分析直接复用这份大盘，每只省约 2.5 分钟。

### 场景 D：验证某个策略靠不靠谱

进「回测」页，选标的与区间跑一遍，重点看**胜率、最大回撤、与买入持有对比**。

## 6. 配置详解

配置文件是项目根目录的 `.env`。改完**必须重启服务**才生效（设置页里改会自动重载）。

### 6.1 大模型

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek 密钥，最省钱 |
| `LLM_MODEL` / `LITELLM_MODEL` | 换模型用；`deepseek-chat` 已被官方标记弃用，报错时改 `deepseek/deepseek-v4-flash` |
| `LLM_TIMEOUT_SEC` | 单次请求超时，网络慢可调大 |

### 6.2 标的与报告

| 变量 | 说明 |
|---|---|
| `STOCK_LIST` | 自选股，逗号分隔。A 股 `600519`、ETF `510300`、美股 `KO` / `BRK.B` |
| `REPORT_LANGUAGE` | `zh` / `en` |
| `MAX_WORKERS` | 并发数，默认 3。调大更快但更容易触发接口限流 |
| `MERGE_EMAIL_NOTIFICATION` | `true` = 所有标的合并成一封邮件（推荐） |

### 6.3 定时任务

| 变量 | 说明 |
|---|---|
| `SCHEDULE_ENABLED` | 是否启用定时 |
| `SCHEDULE_TIME` | 执行时间，默认 `18:00`；多个时间用 `SCHEDULE_TIMES` 逗号分隔 |
| `SCHEDULE_RUN_IMMEDIATELY` | 启动时先跑一次 |
| `TRADING_DAY_CHECK_ENABLED` | `true` = 非交易日自动跳过（建议保持 true） |

### 6.4 网络与代理（本仓库补丁）

| 变量 | 说明 |
|---|---|
| `HTTP_PROXY` / `HTTPS_PROXY` | 本地代理地址，如 `http://127.0.0.1:15732`。**以 `.env` 为准**，会覆盖系统环境变量 |
| `NO_PROXY` | 直连更快的国内源，列在这里不走代理 |
| `EASTMONEY_VIA_PROXY` | `true` = 东财也走代理。**实测不稳定，默认 false** |
| `PROXY_BYPASS_DOMAINS` | 其它需要走代理的域名，逗号分隔 |

### 6.5 性能与数据源

| 变量 | 说明 |
|---|---|
| `MARKET_CONTEXT_REUSE_MINUTES` | 大盘复盘复用窗口（分钟），默认 240。`0` = 每次重新生成 |
| `DAILY_MARKET_CONTEXT_ENABLED` | `false` = 个股报告完全不带大盘环境（省 token，但归因少一块） |
| `TENCENT_PRIORITY` | 腾讯源优先级，本机设 `1`（最快） |
| `EFINANCE_PRIORITY` / `AKSHARE_PRIORITY` | 东财系优先级，本机降权（`9`/`8`） |
| `REALTIME_SOURCE_PRIORITY` | 实时行情源顺序，本机 `tencent,akshare_sina` |
| `ENABLE_CHIP_DISTRIBUTION` | 筹码分布（仅东财），东财不可用时设 `false` |
| `FINNHUB_API_KEY` | 美股实时报价备用源 |

## 7. 数据源与降级链路

系统对每个数据源都有权重，**前面的失败自动降级到后面**。本机实测情况：

| 数据源 | 直连 | 走代理 | 用途 |
|---|---|---|---|
| 腾讯 `qt.gtimg.cn` | ✅ 0.1 s | ✅ | A 股日线主源（38 根 K 线 0.5 s） |
| 新浪 `hq.sinajs.cn` | ✅ | — | 实时行情备用 |
| 东财 `push2*.eastmoney.com` | ❌ 连接被拒 | ⚠️ 时通时断 | 资金流、筹码、换手率 |
| Yahoo `query1.finance.yahoo.com` | ❌ 403 | ✅ 0.1–0.25 s | 美股日线主源 |
| Finnhub | ✅ | — | 美股实时报价（免费版**不含** K 线） |
| 博查搜索 | ✅ | — | 新闻舆情 |

**怎么判断报告里某个字段为什么是空的**：

- 「资金流 / 筹码 / 换手率」为空 → 东财不可达，属预期；
- 「最新消息 / 利好催化」为空 → 没配 `BOCHA_API_KEYS`；
- 美股「量比 / 换手率」为空 → Yahoo 不提供这些字段；
- 报告写「降级兜底」→ 用的是上一交易日收盘价，通常是非交易日。

自查命令（在项目根目录）：

```bash
python -c "import requests;print(requests.get('https://qt.gtimg.cn/q=sh600519',timeout=8).status_code)"
```

## 8. 成本与用量

实测数据（DeepSeek `deepseek-chat`）：

| 项目 | token 量 | 耗时 |
|---|---|---|
| 单只个股分析 | ≈ 10,000 | 3–5 分钟 |
| 单次大盘复盘 | ≈ 5,400 | 2–3 分钟 |

**关键结论**：

- **发邮件不消耗 token、不额外收费**。token 只在"让模型写报告"时消耗，跟发多少封邮件无关。
- 14 只标的每天约 **15 万 tokens**，按 DeepSeek 现价约 **每天几毛到一元**。
- 大盘复用开启后，14 只只跑 1 次大盘 → **每天省约 7 万 tokens、30 分钟**。
- 用量明细随时查：仪表盘「用量」页，或 `GET /api/v1/usage/summary`。

省钱三板斧：

1. 保持 `MARKET_CONTEXT_REUSE_MINUTES=240`（默认已开）；
2. 手动分析时**一次提交多只**（批量共享一份大盘），别一只一只点；
3. 不需要大盘环境时设 `DAILY_MARKET_CONTEXT_ENABLED=false`。

## 9. 定时任务与邮件推送

- 触发条件：`SCHEDULE_ENABLED=true` **且** 当前是交易日（`TRADING_DAY_CHECK_ENABLED=true` 时自动判断）。
- 触发时间：`SCHEDULE_TIME`，默认每天 18:00。
- 输出：跑完所有 `STOCK_LIST` 里的标的，合并成一封邮件（`MERGE_EMAIL_NOTIFICATION=true`）。
- 前置检查：`python main.py --check-notify` 可单独测邮件通道是否正常。

**注意**：定时任务依赖服务进程存活。窗口关了、电脑关机、睡眠，都不会跑。

## 10. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开 8000 端口空白/拒绝连接 | 服务没起来或端口被占 | 看命令行窗口有没有报错；`netstat -ano \| findstr :8000` 查占用 |
| 报告只有结论没有消息 | 未配置搜索 Key | 填 `BOCHA_API_KEYS` |
| 美股全是"获取失败" | 代理没开 | 确认代理客户端在运行，`.env` 里 `HTTP_PROXY` 端口正确 |
| A 股正常、美股全挂 | 代理挂了（A 股走直连不受影响） | 同上 |
| 分析特别慢（>10 分钟/只） | 东财接口反复重试 | 确认 `EFINANCE_PRIORITY=9`、`ENABLE_CHIP_DISTRIBUTION=false` |
| 邮件没收到 | 授权码错 / 进了垃圾箱 / SMTP 未开 | 用 `--check-notify` 单独测；QQ 邮箱用授权码不是密码 |
| 报告报 `deepseek-chat will be deprecated` | 官方弃用警告 | 暂不影响；报错时改 `LITELLM_MODEL=deepseek/deepseek-v4-flash` |
| 改完 `.env` 不生效 | 没重启 | 重启服务 |
| 提示"数据质量低/置信度低" | 关键字段缺失（多为东财不可达） | 属如实标注，不是故障 |

日志位置：项目根目录 `logs/`，或启动窗口里直接看。

## 11. 注意事项（必读）

### ⚠️ 把报告当参考，不要当交易信号

评分是**大模型基于当日公开信息给出的主观判断**，同一只票隔天评分可能大幅漂移。它没有验证过的胜率，也没考虑你的成本、仓位和风险承受度。真要决策，用「回测」页自己验证策略，或用「问股」做多空推演。

### ⚠️ 非交易日的表现不是故障

周末和节假日：没有实时行情，系统自动用上一交易日收盘价；大盘复盘仍会生成。报告里标「非交易日」即此含义。

### ⚠️ 密钥安全

- `.env` 里是明文 Key，**不要提交到 Git**（仓库 `.gitignore` 已忽略）。
- 本项目所在仓库是 **public**，`reports/`、`data/*.db` 也已忽略——但你自己别手动 add。
- 一旦 Key 进过公开仓库，**等于已泄露**，只能去平台重置，删文件没用。

### ⚠️ 数据有延迟、也可能有错

免费源普遍有 15 分钟到数小时延迟，除权处理各源口径不一。看到明显异常的涨跌幅，先去「数据中心」核对原始数据。

### ⚠️ 别把并发开太大

`MAX_WORKERS` 调高会显著增加被封 IP 的概率（尤其东财、Yahoo）。默认 3 够用。

### ⚠️ 定期备份数据库

所有历史报告、持仓、信号都在 `data/stock_analysis.db`（SQLite）。删了不可恢复。

## 12. 升级、备份与迁移

### 备份（建议每周）

```bash
copy data\stock_analysis.db  backup\stock_analysis_20261025.db
```

### 升级到上游最新版

本仓库有三处本地补丁（见 `docs/local-changes.md`），升级时要注意别覆盖：

```bash
git remote add upstream https://github.com/ZhuLinsen/daily_stock_analysis.git
git fetch upstream
git merge upstream/main      # 冲突集中在 src/config.py 与 daily_market_context.py
```

补丁全部可用环境变量关闭，实在冲突就先用上游版本，再决定要不要重打。

### 迁移到新电脑

1. 装 Python 3.13；
2. `git clone` 本仓库，建虚拟环境装依赖；
3. 把旧机器的 `.env` 和 `data/stock_analysis.db` 拷过去；
4. 改 `.bat` 里的虚拟环境路径（如果不是 `dsa-env`）。

## 13. 已知限制

- **A 股资金流/筹码数据缺失**：东财接口在本机网络下不可达，走代理也不稳定。报告会如实标注，不影响技术面判断。
- **美股无资金流**：Yahoo 不提供，属数据源能力边界。
- **Finnhub 免费版不含 K 线**：`/stock/candle` 需付费，本项目美股日线走 Yahoo。
- **新闻搜索依赖博查**：限额内免费，超了会降级为无新闻。
- **无自动更新交易日历**：节假日若判断有误，`--force-run` 可强制跑一次。
- **Windows 优先**：`.bat` 仅 Windows 可用，Linux/macOS 直接用 `python main.py --serve`。
